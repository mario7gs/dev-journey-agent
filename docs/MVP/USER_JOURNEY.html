What the agent changes

Instead of starting implementation from an underspecified request, the team gets a reviewable chain of evidence: repository context, clarified scope, contracts, PRD/TRD, security checks, tests, implementation steps, and stakeholder-ready exports.

The mental model
Give the agent a ticket, let it expose uncertainty, review the evidence, then hand the resulting plan to the team. The agent accelerates planning; the responsible engineer keeps the approval decision.

Bring the request

Start with the request as it exists today. It can be incomplete; the point of Step 0 is to make the missing decisions visible before implementation begins.

  • Provide a ticket with --ticket.
  • Add --repo owner/name when repository context matters.
  • Use mock mode first when learning the workflow.

Install once, then start safely

1. Prepare the environment

# Python 3.11+ and uv are required
uv sync --extra dev

# deterministic mode needs no API keys
cp .env.example .env

Keep USE_MOCK_LLM=true while learning. It prevents accidental provider calls and makes demos repeatable.

2. Run your first request

uv run python src/main.py
--ticket "Add search"
--repo owner/name
--branch main

Blocking mode is the default. If the request has unresolved questions, the command exports a clarification report and exits with a provisional status.

Guided demo: run bash scripts/run_demo.sh to generate a deterministic draft bundle under artifacts/demo/. The wrapper handles the expected provisional exit code for you.

Same journey, different responsibilities

Your job as the junior developer

  • Write the request honestly, including what you do not know.
  • Read the refinement questions before accepting the plan.
  • Use the DoD and TDD roadmap as your implementation checklist.
  • Run the generated tests and return with evidence, not guesses.
  • Resume an interrupted run instead of starting the model work again.

Your job as the responsible engineer

  • Confirm the repository context and scope are appropriate.
  • Challenge assumptions, security notes, contracts, and acceptance criteria.
  • Use the critic gate as evidence, not as a replacement for engineering judgment.
  • Set model, privacy, budget, telemetry, and PDF-renderer policy.
  • Approve the plan only when the traceability chain is complete.

What keeps the journey trustworthy

Blocking is the default

Unresolved refinement questions and high-severity gaps stop approval. Draft mode exists for exploration and stays visibly provisional.

Evidence survives interruption

Each completed stage writes an atomic checkpoint. Resume validates the run configuration and continues from the last completed stage.

Secrets stay outside artifacts

Provider and GitHub credentials come from environment variables. Generated reports, checkpoints, and telemetry are designed to avoid writing secret values.

PDF is an optional presentation surface

Markdown, stakeholder HTML, and case-study HTML remain available if a local Chromium renderer is unavailable. The CLI reports the PDF warning instead of losing the planning record.
